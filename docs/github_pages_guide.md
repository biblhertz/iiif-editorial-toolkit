# Publishing IIIF Manifests on GitHub Pages

This guide explains how to use a free GitHub Pages repository as a manifest server, so the JSON files generated by this tool are accessible at stable public URLs that any IIIF viewer can load.

---

## What GitHub Pages gives you

GitHub Pages serves static files from a repository over HTTPS. It sets `Access-Control-Allow-Origin: *` on all responses, which means IIIF viewers can fetch your manifests from any origin. There is no cost, no server to maintain, and no configuration beyond enabling the feature.

**What it hosts:** your manifest JSON files.
**What it does not host:** the images themselves. Images continue to be served by whichever IIIF image server holds them (your institution, Wikimedia, a third-party service). For viewers to display images, that image server must also allow cross-origin requests — GitHub Pages has no effect on that.

---

## Step 1 — Create a repository

1. Sign in to [github.com](https://github.com).
2. Click **+** → **New repository**.
3. Give it a short, stable name, for example `iiif-manifests`.
4. Set visibility to **Public** (required for free GitHub Pages).
5. Check **Add a README file** so the repository is not empty.
6. Click **Create repository**.

---

## Step 2 — Enable GitHub Pages

1. In your repository, go to **Settings** → **Pages** (left sidebar).
2. Under **Source**, select **Deploy from a branch**.
3. Choose branch **main** and folder **/ (root)**.
4. Click **Save**.

After a few seconds, GitHub will display the site URL:

```
https://your-username.github.io/iiif-manifests/
```

This is your **Base URL**. Keep it; you need it in the next step.

---

## Step 3 — Set the Base URL in the generator

Open `iiif_generator.html` in your browser.

In the **Individual Images** tab, find the **Base URL** field and enter your GitHub Pages URL, ending with a slash:

```
https://your-username.github.io/iiif-manifests/
```

Do the same in the **Comparison Layouts** tab → **Manifest details** → **Base URL**.

All manifests you generate from this point forward will have their `id` field pointing to the correct public URL.

---

## Option A: Direct publishing from the generator (recommended)

Once your repository is set up, you can publish manifests directly from the tool without downloading and uploading files manually.

### Step 3a — Create a Personal Access Token

1. On github.com, click your profile avatar → **Settings** → **Developer settings** → **Personal access tokens** → **Tokens (classic)**.
2. Click **Generate new token (classic)**.
3. Give it a descriptive name, for example *IIIF Generator*, and set an expiry (one year is practical).
4. Under *Select scopes*, check **repo** only — this gives the token write access to your repository.
5. Click **Generate token**. **Copy it immediately** — GitHub only shows it once.

### Step 3b — Configure publish settings in the generator

1. Open `iiif_generator.html` in your browser.
2. Click **⚙ Publish settings** in the top-right corner of the tool.
3. In the *GitHub Pages* section, paste your token in **Personal Access Token**.
4. Enter your repository as `username/iiif-manifests` in **Repository**.
5. Leave **Branch** as `main` (or change it if your repository uses a different default branch).
6. Select **GitHub Pages** as the default destination.
7. Click **Save settings**.

The tool will automatically populate all Base URL fields with your GitHub Pages URL.

### Step 3c — Publish

Generate any manifest, then click the teal **Publish** button (next to **Download JSON**). The manifest is pushed directly to your repository and the public URL is shown immediately with a **Copy URL** button.

There is no need to download and re-upload the file. Allow up to 60 seconds for GitHub Pages to deploy newly published files.

---

## Option B: Manual upload (fallback)

## Step 4 — Generate and download a manifest

Fill in the image details, click **Generate Manifest**, then **Download JSON**. The file will be saved with a name matching the Manifest ID, for example `a3f5b2c9d1e8.json`.

If you want a human-readable filename, edit the **Manifest ID** field before generating. Use lowercase letters, numbers, and hyphens only — for example `raphael-transfiguration-1520`. The download will be named accordingly.

---

## Step 5 — Upload the JSON file to GitHub

1. In your repository on github.com, click **Add file** → **Upload files**.
2. Drag the downloaded `.json` file onto the upload area.
3. Add a short commit message, for example `Add manifest: Raphael Transfiguration`.
4. Click **Commit changes**.

The file is now live. Allow up to 60 seconds for GitHub Pages to deploy it.

Your manifest is accessible at:

```
https://your-username.github.io/iiif-manifests/a3f5b2c9d1e8.json
```

---

## Step 6 — Test the manifest

Return to the generator and open the **Validation & Testing** tab. Paste the public URL and click:

- **Validate manifest** — checks IIIF Presentation 3 compliance.
- **Test viewer compatibility** — opens links to load the manifest in Mirador 3, TheseusViewer, and Universal Viewer.

---

## Updating a manifest

If you edit metadata and regenerate, download the new JSON and upload it to the same filename in GitHub. The existing file is overwritten. Viewers that have previously cached the manifest may need a hard refresh.

---

## Organising multiple manifests

For a small number of manifests, a flat folder works well. For larger collections, create subfolders in the repository (for example by project or date) and adjust the Base URL accordingly:

```
https://your-username.github.io/iiif-manifests/project-a/
```

Upload files into that subfolder using **Add file** → **Upload files** after navigating into the folder, or via the GitHub web editor.

---

## Sharing a set of manifests as a collection

A IIIF Collection manifest lists multiple manifests under a single URL, letting viewers present them as a browseable set.

1. In the generator, open the **Manifest Library** tab.
2. Scroll to the **Generate Collection Manifest** section at the bottom.
3. Enter a collection title, choose a language, and set the Base URL to your GitHub Pages URL.
4. Click **Generate Collection**, then **Download collection.json**.
5. Upload `collection.json` to your GitHub repository alongside the individual manifest files.

Your collection is now live at:

```text
https://your-username.github.io/iiif-manifests/collection.json
```

Share this URL with colleagues — Mirador 3 and Universal Viewer will present all listed manifests in a single browseable interface.

The collection includes a thumbnail for each item (fetched from the image server), so viewers that support thumbnail grids will display a visual overview of the set.

---

## Notes on image CORS

GitHub Pages only affects how your manifest JSON files are delivered. Whether images load in a viewer depends entirely on the image server's CORS policy:

- **Fotothek Bibliotheca Hertziana, Wikimedia, many major institutions**: CORS is open, images load in any viewer.
- **Some institutional servers**: CORS is restricted. Viewers can open the manifest but images appear broken. Contact the server administrator or use the institution's own viewer.

There is nothing in the manifest itself that can override a server's CORS policy.
